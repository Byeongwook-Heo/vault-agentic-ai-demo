# 발표용 데모 순서

## 시작

챗봇을 열고 라이트/다크 모드를 선택합니다. 신원·권한 경로의 상태는 요청 단위로 보여주며, 로그인만으로 DB 접근이 완료된 것으로 설명하지 않습니다.

## 시나리오 A · 미승인 사용자

1. Verify에 로그인하지 않은 상태에서 “안녕?” 또는 “이 Lab의 보안 흐름을 설명해줘”를 입력합니다.
2. 일반 AI 응답을 확인합니다.
3. “주문 ORD-1001 상태 확인해줘”를 입력합니다.
4. 데이터 접근이 Agent에서 거부되고 OBO·MCP·Vault·DB가 호출되지 않는 것을 설명합니다.

## 시나리오 B · 전체 승인

1. Verify에서 `orders-full` 사용자를 인증합니다.
2. ORD-1002 상태와 최근 주문 목록을 요청합니다.
3. 사용자 JWT → Agent의 KMS 서명 → Verify OBO 교환 → Gateway → MCP → Vault → DB를 설명합니다.
4. 각 단계를 클릭하여 수행 내용과 예시 코드를 보여줍니다.
5. 코드 팝업은 학습용 예시이며 실제 토큰/비밀번호를 노출하는 화면이 아님을 설명합니다.

## 시나리오 C · 제한 승인

1. 로그아웃하고 Verify에서 `orders-limited` 사용자로 로그인합니다.
2. ORD-1001은 조회되지만 ORD-1002는 “권한 없음 또는 찾을 수 없음”으로 표시되는지 확인합니다.
3. 최근 주문·실패 결제 통계도 제한된 범위임을 확인합니다.
4. 인증 성공과 데이터 권한 승인은 다르다는 점을 강조합니다.

## 선택 · 역할 비교 리포트

`make demo-access-report`는 두 tier의 Vault/DB 권한을 한 번에 비교합니다. CodeBuild 작업이며 실제 두 계정의 사용자 로그인을 수행하는 것은 아닙니다. 행사 전에 실행하고 결과를 준비하면 시작 대기를 줄일 수 있습니다.

토큰, private key, DB 비밀번호, 운영자 root token은 화면 공유하지 않습니다.
